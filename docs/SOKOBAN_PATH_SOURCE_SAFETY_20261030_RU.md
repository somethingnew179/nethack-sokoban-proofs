# Исходные ветви для восьми полных путей

Это конечный аудит **точных восьми свидетелей**, а не универсальная теорема
соответствия C/Lean. `path_safety_check.py` независимо повторяет каждое
индивидуальное движение координатами/множествами, проверяет коллизии и углы,
инвентаризирует C-ветви, связывает предложения и исходники SHA256. При
`--native` он дополнительно сравнивает финал и cost с существующим Lean CLI;
он не строит Lean и не исполняет весь исходный `moverock_core/launch_obj`.

Все полные пути: настоящая каноническая исходная карта → все исходные
PIT/HOLE заполнены. Для каждого из них нет качения по лестнице вниз/branch
entry, столкновения катящегося валуна с другим валуном или intact door.
На картах 1/2/3 все срабатывания RLT направлены на восток; на 4 — на север
или запад. Свидетель 4-2 здесь **85/332**, совпадающий с kernel-путём;
отдельный прежний proposer 85/322 в эту таблицу не подменён.

Первичный источник — commit
`b0c09c878e1f9f62bc7ab20e6edafd6108c325a0`:

* `src/hack.c:166–215,348–640`: обычное `dopush` не вызывает лестничную
  отправку. Поэтому 11 обычных толканий на/с `(6,11)` в 2-2 безопасны
  относительно этой конкретной ветви. Начальная клетка качения тоже не
  проверяется `down_gate` как уже пройденная клетка полёта.
* `src/hack.c:595–614`, `src/trap.c:3263–3585`: RLT вызывает `launch_obj`;
  клетки его прямой траектории проверены. `trap.c:3427–3434` вызывает
  `down_gate`/`ship_object`, поэтому отсутствие лестницы на этих конкретных
  траекториях существенно. Это не утверждение об остальных состояниях карт.
* `src/dokick.c:1679–1684`: для `BOULDER + is_hole` отправка возвращает FALSE,
  и caller заполняет HOLE. Поэтому 15/18/10/11/15/12 попаданий RLT в HOLE
  на картах 1-1/1-2/2-1/2-2/3-1/3-2 не требуют удачного исхода отправки.
  RNG при этом может расходоваться; распределение случайности не утверждается.
* `hack.c:531–566`, `trap.c:3492–3507`, `do.c:162–272`: заполнение PIT/HOLE
  потребляет валун при предпосылках отсутствия других акторов и предметов.

Предпосылки остаются видимыми: обычный способный наземный герой, отсутствие
мешающих статусов/монстров/других предметов, действий с инструментами,
телепортов, squeeze, новых валунов/ловушек, rolling collisions/door breaking
и входа героя в открытую яму. Goal не включает получение награды, проход
лестницы после снятия Sokoban rules или победу во всей игре. Moves — успешные
перемещения, без отождествления с игровыми часами C. Этот аудит не доказывает
оптимальность; соответствующие Lean-теоремы имеют собственные границы.

Текущий повтор без нового native-запуска: `path-safety/result.json`, status
`PASS_EIGHT_FULL_WITNESS_SOURCE_BRANCH_INVENTORIES`. Предложения и C/Lua
побайтно сверены с pin; все input/proposal/source SHA записаны в отчёте.
Новые четыре kernel-свидетеля связаны прежним замороженным
`continuation13/full-paths/handoff.json`; оригинальные четыре — сохранёнными
`validation/sokoban/solver/*-improved-solution.json`.

После стабилизации movement batch повтор с native (из каталога `lean`):

```sh
python3 .validation/sokoban/continuation13/source-gate/path_safety_check.py --lean-root "$PWD" --output "$PWD/.validation/sokoban/continuation13/source-gate/path-safety-native" --native
```

Этот helper/reference находится в staging. Постоянный reflection gate
подготовлен отдельно в `validation/sokoban/source/symmetry_check.py` внутри
этого staging и не зависит от временных результатов прежних проверок.
